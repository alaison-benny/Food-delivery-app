# 🍔 Food Delivery App - EKS Deployment Guide

ഈ പ്രോജക്റ്റ് ഒരു മൈക്രോസർവീസസ് അധിഷ്ഠിത ഫുഡ് ഡെലിവറി ആപ്ലിക്കേഷനാണ്. ഇത് **Amazon EKS** (Elastic Kubernetes Service) ഉപയോഗിച്ച് AWS ക്ലൗഡിൽ എങ്ങനെ ഡിപ്ലോയ് ചെയ്യാം എന്നതിനെക്കുറിച്ചുള്ള പൂർണ്ണമായ വിവരങ്ങൾ താഴെ നൽകുന്നു.

## 🚀 പ്രോജക്റ്റ് വിവരണം (What is our Project?)

കണ്ടെയ്നറൈസ് ചെയ്ത മൈക്രോസർവീസുകളെ ക്ലൗഡിൽ മാനേജ് ചെയ്യുന്ന ഒരു ആർക്കിടെക്ചറാണ് ഈ പ്രോജക്റ്റ്. ഉപയോക്താക്കൾക്ക് മെനു കാണാനും ഓർഡറുകൾ നൽകാനും സഹായിക്കുന്ന രീതിയിലാണ് ഇത് ഡിസൈൻ ചെയ്തിരിക്കുന്നത്. ഇതിനായി **AWS Load Balancer Controller** ഉപയോഗിച്ച് ഒരു പബ്ലിക് ഇൻഗ്രെസ്സ് ഗേറ്റ്‌വേ സജ്ജീകരിച്ചിരിക്കുന്നു.

---

## 🛠️ ഇന്ന് നമ്മൾ ചെയ്ത പ്രധാന സ്റ്റെപ്പുകൾ (Steps Done Today)

ഇന്ന് ആപ്പ് ലൈവ് ആക്കുന്നതിനായി നമ്മൾ താഴെ പറയുന്ന പ്രധാന ജോലികൾ പൂർത്തിയാക്കി:

1. **IAM Policy Update:** ലോഡ് ബാലൻസർ കൺട്രോളറിന് ആവശ്യമായ പുതിയ പെർമിഷനുകൾ (v2.7.1) `v4` പോളിസി വേർഷനിലൂടെ അപ്‌ഡേറ്റ് ചെയ്തു.
2. **Controller Refresh:** പുതിയ പോളിസി പ്രാബല്യത്തിൽ വരാൻ സർവീസ് അക്കൗണ്ട് റീഫ്രഷ് ചെയ്യുകയും കൺട്രോളർ റീസ്റ്റാർട്ട് ചെയ്യുകയും ചെയ്തു.
3. **Subnet Tagging:** ഇൻഗ്രെസ്സ് അഡ്രസ്സ് ലഭിക്കുന്നതിനായി പബ്ലിക് സബ്നെറ്റുകളിൽ `kubernetes.io/role/elb: 1` എന്ന ടാഗ് ഉണ്ടെന്ന് ഉറപ്പുവരുത്തി.
4. **Ingress Creation:** AWS Application Load Balancer (ALB) വിജയകരമായി നിർമ്മിക്കുകയും ഒരു പബ്ലിക് URL (`k8s-default-foodappi...`) ലഭിക്കുകയും ചെയ്തു.
5. **Cluster Scaling:** ക്ലസ്റ്ററിൽ പോഡുകൾ റൺ ചെയ്യാൻ സ്ഥലം ഇല്ലാത്ത പ്രശ്നം (Insufficient CPU/Pods) പരിഹരിക്കാൻ നോഡ്ഗ്രൂപ്പ് സ്കെയിലിംഗ് കമാൻഡുകൾ ഉപയോഗിച്ചു.
6. **Troubleshooting 503 Error:** `Pending` സ്റ്റേറ്റിലായിരുന്ന പോഡുകളെ `Running` സ്റ്റേറ്റിലേക്ക് എത്തിച്ച് ലോഡ് ബാലൻസർ ഹെൽത്തിയാണെന്ന് ഉറപ്പുവരുത്തി.

## 🔍 പ്രധാന കമാൻഡുകൾ (Quick Reference)

* **ലോഗുകൾ പരിശോധിക്കാൻ:** `kubectl logs -n kube-system -l app.kubernetes.io/name=aws-load-balancer-controller`
* **ഇൻഗ്രെസ്സ് കാണാൻ:** `kubectl get ingress`
* **പോഡുകൾ നോക്കാൻ:** `kubectl get pods`
* **നോഡ് സ്കെയിലിംഗ്:** `eksctl scale nodegroup --cluster=food-delivery-cluster --name=ng-975e022d --nodes=4`

# How to rebuild this project in future?
ഭാവിയിൽ ഈ പ്രോജക്റ്റ് വീണ്ടും റീബിൽഡ് ചെയ്യാൻ വളരെ ലളിതമായ 5 ഘട്ടങ്ങൾ താഴെ നൽകുന്നു. നമ്മൾ ഇന്ന് കഷ്ടപ്പെട്ട് കണ്ടെത്തിയ പരിഹാരങ്ങൾ (Fixes) ഉൾപ്പെടുത്തിക്കൊണ്ടുള്ള സ്റ്റെപ്പുകളാണിവ:

### 🛠️ ഭാവിയിൽ റീബിൽഡ് ചെയ്യാനുള്ള ഘട്ടങ്ങൾ:

**1. ക്ലസ്റ്റർ ക്രിയേറ്റ് ചെയ്യുക (Create Cluster):**
ആദ്യം `eksctl` ഉപയോഗിച്ച് ക്ലസ്റ്റർ നിർമ്മിക്കുക.

```bash
eksctl create cluster --name food-delivery-cluster --region us-east-2 --nodes=4 --node-type=t3.micro

```

> **ശ്രദ്ധിക്കുക:** തുടക്കത്തിലേ തന്നെ `--nodes=4` നൽകുന്നത് പിന്നീട് വരാനിരുന്ന 'Too many pods' എറർ ഒഴിവാക്കാൻ സഹായിക്കും.

**2. IAM Policy & OIDC സെറ്റപ്പ്:**
ലോഡ് ബാലൻസറിന് ആവശ്യമായ പെർമിഷനുകൾ നൽകുക.

* OIDC എനേബിൾ ചെയ്യുക: `eksctl utils associate-iam-oidc-provider --cluster food-delivery-cluster --approve`
* നമ്മൾ ഇന്ന് പുതുക്കിയ `v4` പോളിസി ഉപയോഗിച്ച് IAM റോൾ ക്രിയേറ്റ് ചെയ്യുക.

**3. AWS Load Balancer Controller ഇൻസ്റ്റാൾ ചെയ്യുക:**
Helm ചാർട്ട് ഉപയോഗിച്ച് കൺട്രോളർ ഇൻസ്റ്റാൾ ചെയ്യുക. സർവീസ് അക്കൗണ്ട് ശരിയായി ലിങ്ക് ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പുവരുത്തുക.

**4. സബ്നെറ്റ് ടാഗിംഗ് (Subnet Tagging):**
VPC സെക്ഷനിൽ പോയി പബ്ലിക് സബ്നെറ്റുകളിൽ താഴെ പറയുന്ന ടാഗ് ഉണ്ടെന്ന് ഉറപ്പാക്കുക:

* **Key:** `kubernetes.io/role/elb`, **Value:** `1`.

**5. ആപ്ലിക്കേഷൻ ഡിപ്ലോയ്മെന്റ് (Deploy Apps):**
നിങ്ങളുടെ YAML ഫയലുകൾ ഈ ക്രമത്തിൽ അപ്ലൈ ചെയ്യുക:

1. `deployment.yaml` & `service.yaml` (Menu & Order services).
2. `ingress.yaml` (ഇത് അപ്ലൈ ചെയ്യുമ്പോൾ ALB തനിയെ ക്രിയേറ്റ് ചെയ്യപ്പെടും).

### 💡 റീബിൽഡ് ചെയ്യുമ്പോൾ ഓർമ്മിക്കാൻ ചില കാര്യങ്ങൾ:

* **Health Checks:** നിങ്ങളുടെ ആപ്പിലെ പാത്തുകൾ (`/menu`, `/order`) ഇൻഗ്രെസ്സ് ഫയലിലെ `healthcheck-path`-ൽ കൃത്യമായി നൽകുക.
* **Resource Limits:** ചെറിയ ഇൻസ്റ്റൻസുകൾ (t3.micro) ഉപയോഗിക്കുമ്പോൾ റപ്ലിക്കകളുടെ എണ്ണം കുറച്ചു നിർത്താൻ ശ്രദ്ധിക്കുക.
